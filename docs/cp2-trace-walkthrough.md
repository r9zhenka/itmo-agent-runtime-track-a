# ЧП2: два конкретных трейса

Это разбор сохранённой кампании **39 задач × 3 повтора**, проведённой на версии
`9555ba9` 19–20 ноября 2026 UTC. Исправления клиента и чекеров на `ea39ddc` не
меняют события этих запусков. Первая пара — собственный харнес и
`deepseek-ai/DeepSeek-V4.1-Flash-1017` через API курса.

Полные сохранённые события находятся в
[`live-cp2-events.json`](evidence/cp2/live-cp2-events.json), метаданные сервера — в
[`live-cp2-trace-map.json`](evidence/cp2/live-cp2-trace-map.json). Они содержат
фиксированные учебные данные, без ключей API или клиентских токенов. Значение
`seq` задаёт порядок событий внутри сессии; `run_id` совпадает с `trace_id`.
`operation_id` связывает начало и результат одного инструмента.

В этой исторической версии событие `model` хранит модель, время и использованные
токены, а `tool_start` — имя инструмента и ID операции. Полные HTTP-запросы модели
и аргументы вызовов инструментов в эти события не включались. `tool_result`
содержит stdout/stderr и статус исполнения. Поэтому ниже отделены факты событий
от того, что следует из контракта задачи и кода. Неизвестные запросы или скрытое
рассуждение модели не восстанавливаются по догадке.

## Успех: B1.1, повтор 1

Задача просит прочитать конфигурацию и записать порт сервиса в `answer.txt`.
Фикстура создаётся раннером в новой папке клиента, экспортируется через
WebDAV → SSH → rclone/FUSE и доступна контейнеру как `/work`.

- Сессия: `098ed3b27fb74d22a857c5b23f1cba24`.
- Запуск/трейс: `a4892be194344978b90b5befd0ce7853`.
- Фикстура: `workspaces/baf-B1-1-e84eb107e3`.
- Исходный результат: вторая строка [`live-cp2.jsonl`](evidence/cp2/live-cp2.jsonl).
- Итог независимого чекера: `pass=true`; задача не входила в область переоценки.

| seq | Событие и переход между компонентами | Наблюдение | Время, мс / токены |
|---:|---|---|---|
| 1 | `started`: gateway передал сообщение харнесу | Принят новый запуск | — |
| 2 | `model`, шаг 0: харнес → LLM-прокси → провайдер → харнес | Ответ модели получен | 3722.720 / 647 |
| 3–4 | `ReadFile`: харнес → менеджер → контейнер → менеджер → харнес | stdout содержит `service`, `name: demo`, `port: 8137`; exit 0 | 1135.814 |
| 5 | `model`, шаг 1 | Следующий ответ после результата чтения | 3694.778 / 847 |
| 6–7 | `WriteFile` | stdout `written`, exit 0 | 1496.157 |
| 8 | `model`, шаг 2 | Следующий ответ после записи | 3577.488 / 1007 |
| 9–10 | `RunCommand` | stdout `8137`, exit 0 | 1173.974 |
| 11 | `model`, шаг 3 | Последний ответ модели | 3672.639 / 1162 |
| 12 | `result`: харнес → gateway → клиент | Единственный финальный `outcome=success` | 19168.112 / 3663 суммарно |

Например, `ReadFile` связывается по
`operation_id=a4892be194344978b90b5befd0ce7853-0-0` в seq 3 и 4. Передача файлов
идёт через смонтированную файловую систему; RPC содержит команды и их результат.
Возврат к следующему событию `model` означает, что харнес продолжил цикл после
инструмента. Условия этого перехода видны в [коде харнеса](../runtime/harness.py).

647 + 847 + 1007 + 1162 = **3663 сообщённых токена**. Это сумма usage ответов,
а не длина итогового сообщения. Серверный `result.duration_ms` равен **19.168 с**;
раннер записал **20.650 с** от начала своей процедуры до результата проверки.
Разные границы измерения включают установление сессии и работу клиентского
протокола; их нельзя считать одним и тем же таймером.

После финального события раннер проверяет `answer.txt` и освобождает сессию.
Эти действия не представлены дополнительными `seq` в данном агентном трейсе:
вердикт хранится в JSONL раннера, а удаление контейнеров/монтирования отдельно
проверено [acceptance-сценариями](evidence/cp2/README.md). По одному `success`
нельзя доказать очистку всех ресурсов.

## Неуспех: C3, повтор 2 — клиент отменил ещё работающий запуск

C3 объединяет чтение спецификации, реализацию `parse_duration`, тесты, запуск
CLI и ограниченную правку README. Эта попытка осталась неуспешной после
исправления чекеров и после отдельного успешного follow-up.

- Сессия: `5c9dac02a48f4e10b779214429b22b85`.
- Запуск/трейс: `94e05e9b51e649acbf7712060ee647f0`.
- Фикстура: `workspaces/baf-C3-ce2f50a658`.
- Последний серверный результат: seq **51**, `outcome=cancelled`.
- Ошибка раннера: `Timed out waiting for run; reconnect using the last event ID`.

| seq | Что произошло | Что это позволяет установить |
|---:|---|---|
| 1 | `started` | Сервер принял запуск |
| 2–42 | 11 ответов модели и инструменты | Агент читал спецификацию, создавал и проверял файлы; каждый ответ добавляет usage и имеет свой таймер |
| 43–44 | `RunCommand`, exit 0; stdout `ALL EDGE CASES OK`, `EXIT=0` | Наблюдаемое сообщение публичной проверки; оно само по себе не заменяет скрытые тесты |
| 45 | `model`, шаг 11, 10864.871 мс, 8722 токена | Харнес продолжает цикл, финального ответа ещё нет |
| 46–47 | `RunCommand`, exit 0 | В stdout видны CLI-ответ `3723`, три тестовых метода, содержимое `main.py` и README; stderr содержит успешный unittest-отчёт |
| 48 | `model`, шаг 12, 6982.624 мс, 9382 токена | Получен ещё один ответ модели |
| 49–50 | `RunCommand`, внешний exit 0; stdout `/bin/sh: 1: git: not found`, `EXIT=0` | В образе нет Git. Обёртка вернула 0, поэтому это не стало фатальной ошибкой инструмента |
| 51 | `result`, `cancelled`, 210432.511 мс, 72490 токенов | Первое терминальное событие неуспеха: отмена примерно на 210-й секунде |

Причина отмены устанавливается **по нескольким источникам**, а не по одному
слову `cancelled`: клиентская ошибка ожидания, прежний лимит `Client.watch`
**210 с** в версии `9555ba9`, серверный бюджет **600 с** и время seq 51.
В финализаторе раннера освобождение сессии вызывает отмену продолжающегося
запуска. Ошибка `git: not found` в seq 50 — отдельное ограничение образа;
данные не устанавливают её причиной истечения клиентского ожидания.

Прежний обработчик исключения потерял session/trace ID и промежуточный usage.
Метаданные восстановлены в отдельном файле по единственной неизвестной сессии
среди 117 серверных трейсов, единственной несопоставленной C3-папке и
наблюдаемой C3-спецификации. [Аудит восстановления](evidence/cp2/live-cp2-reconciliation-audit.json)
сохраняет исходную строку, новую строку и SHA256 обоих файлов. Исходные `pass=false`,
`error_kind=timeout` и причина не изменены.

Сумма 13 полученных `model.tokens` — **72 490**. Вызов, который мог выполняться
при отмене, способен иметь неучтённую стоимость: это известный subtotal, а не
точный счёт провайдера. Клиентский end-to-end таймер потерян; серверные
**210.433 с** не вставляются вместо него. Поэтому общая статистика длительности
имеет n=116, а для C3 — n=2 при трёх попытках в знаменателе качества.

Исправленный клиент ждёт до 900 с и сохраняет частичные метаданные. Отдельный
[C3 follow-up](c3-followup.md) дал 3/3, но его запуски не заменяют эту отмену.
Все три follow-up завершили генерацию раньше 210 с, поэтому они отдельно не
доказывают причинный эффект увеличения лимита.

## Где впервые видна ошибка модели, в отличие от отмены

Для сравнения: B2.1, повтор 1, сессия
`e2ce5eab680c41f8b34701878b321499`, заканчивается в **seq 13** с
`outcome=error`, `error.kind=model`. Предыдущий инструмент (seq 12, WriteFile)
завершился успешно. Из этой исторической ошибки известно только, что этап
обращения к провайдеру не дал допустимого ответа; конкретный HTTP-статус,
транспортная причина или finish reason в том трейсе отсутствуют. **3393** токена
учтены по полученным ответам; стоимость неудачного обращения неизвестна.
Поэтому отчёт не приписывает этот случай конкретному поведению модели без данных.

## Открыть эти события без сервера и без обращения к модели

Из корня репозитория:

```bash
python3 - <<'PY'
import json
from pathlib import Path
history = json.loads(Path('docs/evidence/cp2/live-cp2-events.json').read_text())
for sid in ('098ed3b27fb74d22a857c5b23f1cba24',
            '5c9dac02a48f4e10b779214429b22b85'):
    print('SESSION', sid)
    for event in history[sid]:
        print(json.dumps(event, ensure_ascii=False))
PY
```

Это чтение уже опубликованных учебных событий. Команды кандидата из JSON не
исполняются. Общая [архитектура](cp2-architecture.md),
[правила переоценки](evaluation-corrections.md) и
[матрица качества](live-results.md) связывают этот разбор с остальными материалами.
